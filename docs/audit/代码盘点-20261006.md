## 四、Python 残留清单（22,263 行 / 107 文件，含测试）

> ★ **本节行数为 `wc -l` 物理行**（含注释与空行），与第二节的「净代码行」口径不同，通常打 7~8 折。
> 例：`plugins/web` 物理 11,748 行 ≈ 净 8,600 行。

按**归属**分五类（判定依据 = 板端实查）：

### ① 死代码 — 11,748 行（可以删）

| 路径 | 行数 | 为什么是死的 |
|---|---|---|
| `plugins/web/bin/ttbox-web.py` | 1,133 | Flask 后端。service 的 `TTBOX_WEB_BACKEND=cpp` ⇒ 走 C++ `ttbox_web` |
| `plugins/web/api_v1.py` | 882 | 同上 |
| `plugins/web/lib/*.py` | ~2,500 | calibration / profile_translate / branding 等 |
| `plugins/web/api/*.py` | ~1,500 | hardware / models 等（C++ `domain/` 已重写） |
| 其余 `plugins/web/**` | ~5,700 | 框架与辅助 |

**唯一保留价值**：`TTBOX_WEB_BACKEND=py` 是回退分支。删掉就把回退能力也删了。

### ② 板端在用 — 223 行（下一步 C++ 化的目标）

`plugins/preview/bin/ttbox-preview.py`（223 行）—— **板端唯一的 TTBOX Python 常驻进程**，监听 `127.0.0.1:8001`。
C++ `preview.cpp` 已能直连 IPC 取帧，**只在 IPC 完全不可达时回退 8001** ⇒ 它是降级兜底。

### ③ 事件触发（板端会用，非常驻）— 约 2,800 行

`scripts/` 下的运维脚本：`ttbox_ota_updater.py` 616 行（升级时跑）、`wifi_manager.py` 848 行
、`ttbox_m207_accept.py` 1216 行 / `ttbox_m2xx_console_accept.py` 609 行（验收工具）、`legacy/*` 496 行。

`framework/`（977 行，插件管理框架）+ `ttbox_platform/`（494 行，配置分层/健康/模型生命周期）。

## 六、结论

1. **运行时 C++ 化已接近完成**：板端 2 个 TTBOX 服务里，8000 面板是 C++，只剩 8001 预览是 Python。
   干掉它 = 板端 TTBOX 运行时 100% C++。
2. **代码库 C++ 化还差一大块**：`plugins/web/` 11,748 行 Python（物理行）是死代码，按净代码行算约占产品 Python 的 45%。
   删掉后产品 Python 从 23.3% 降到 **约 14%**，C++ 从 44.5% 升到 **约 50%**。
3. **`framework/` + `ttbox_platform/` 是纯仓库负担**：1,471 行、板端不跑、只服务测试。
   清理前要先比对 core 里是否已有 C++ 同名实现（配置分层、模型生命周期、插件管理）——若有就是合并而非删除。
4. **JS/CSS 9,894 行是前端的天然组成**，不算"未 C++ 化"的对象。

**建议动作顺序**：② 预览下线 → ① Web 死代码清理 → ③ 平台层比对合并。
