## 0. 为什么现在能动，以及三条不能碰的线

### 三条硬约束

1. **URL 一个字不能改。** 84 条路由的路径、方法、参数名、返回 JSON 结构全部冻结。
   前端 `index.html` 里 12 个写死的 `/api/...` 加一批模板拼接的路径全指着它们。
2. **入口文件名不能改。** `deploy/systemd/ttbox-web.service:23` 是
   `ExecStart=/opt/ttbox/current/plugins/web/bin/ttbox-web`（bash shim），
   shim 里 `exec python3 "$PLUGIN_DIR/bin/ttbox-web.py"`。
   ⇒ `bin/ttbox-web.py` 必须保留原名，且**必须仍能单独执行**。
3. **规矩 §4.2 行数**：新增文件 ≤300 行；存量文件被修改不得跨过下一个 100 行位。
   6099 行 ⇒ 至少 21 个文件；`_calib_worker`（358 行）这种单体还要再拆。

### ★★ 真正的难点：482 个测试的两条隐式硬约束

`plugins/web/tests/*.py` 用 `importlib.util.spec_from_file_location` 动态加载入口文件，
然后**直接对模块级全局打补丁**。

**约束 A —— `monkeypatch.setattr(<入口模块>, '<名>')` 共 130 处 / 13 个测试文件。**
全量清单（2026-10-02 实测，按出现次数）：


★ 第一版清单（只列了 10 个高频名）**漏了 17 个**，其中 `_calib_sample_pair` 直接导致
S4 首轮搬迁被测试打回 —— 教训：**清单必须机械枚举，不能靠"高频几个"拍脑袋**。

含义：某个函数一旦搬走，它读的就是新模块的全局，入口模块上打的补丁对它不再生效 ⇒ 假绿。

**约束 B —— 7 个测试直接读入口源码文本**（`str.index` 切片后 `exec` / `ast` 抽函数段 /
纯 `in` 断言，三种形状都有；详见 §2 末的逐个改法表）。
★ S4 时按 5 个准备，S5/S6 实测又发现 2 个（`test_web_aim_head_box.py` 的 `in` 断言、
`test_web_ota_version_scheme.py` 的 `ast` 抽函数）—— 与约束 A 同一教训：**要机械枚举**。

#### 解法：`plugins/web/lib/hub.py`（动态查找点 / service locator）

- 被补丁的名字**一律留在入口模块**（原样定义或 re-export），补丁照样打在入口上；
- 搬进 `lib/` 的模块**不在 import 期快照这些名字**，改为**调用时** `hub.get('X')` /
  `hub.call('X', ...)` 向入口取 → 补丁在调用那一刻才解析，落得实；
- 入口末尾 `hub.bind(sys.modules[__name__])`（必须用 `__name__` —— 测试给入口起的是
  `ttbox_web_<主题>_<pid>_<n>` 这种动态名字，写死 `ttbox-web` 会 bind 到别的实例）；
- 转发函数一律写 `def f(*args, **kwargs)` 透传 —— 测试的替身常是少参数的 `lambda`，
  固定补默认值会在转发时多塞实参而 `TypeError`。

★ 有两条反例要记住：
1. **`_CFG_WRITE_LOCK` 这类"共享对象"不能各模块各 new 一把**（各自 new = 没加锁）。
   单点放 `lib/locks.py`，入口与各 lib import **同一个对象**。同时**消费点必须写裸名**
   `with _CFG_WRITE_LOCK:`（测试用 exec + 命名空间注锁，写成 `hub.get(...)` 就注不进去了）。
2. **`_license_block`（12 处补丁）与 `_ui_block`（1 处）目前都定义在 `lib/branding.py`**，
   而 `branding.py:321` 内部会调 `_license_block()` —— 这条路径打补丁**不生效**。
   现役 482 个用例没踩到（打补丁的用例走的是入口侧调用链），但属于**已知隐患**，S9 拆蓝图时一并处理。

任何一步不绿就停在那里修，绝不带着红灯往下搬。

## 3. 前端 index.html 拆分

现状：单文件 13446 行，纯裸 DOM + 全局函数，`<script>` 内联 11218 行。

拆分口径（**HTML 结构一个字不动**，只搬 CSS/JS 到外链）：

| 产物 | 内容 | 约束 |
|---|---|---|
| `templates/index.html` | 只留 HTML 骨架 + `<link>` + `<script src>` | 结构、id、class 全保留 |
| `static/panel.css` | 原 `<style>` 段（5188 行） | 拆成 3–4 个文件，每个 ≤300 行？**CSS 不受 §4.2 约束**（规矩只管代码文件），但仍按主题/布局/组件分片便于维护 |
| `static/panel/*.js` | 原内联 JS（11218 行） | 按域拆：`core.js`(state/api 封装) / `pages-*.js` / `calib.js` / `motion.js` … |

**关键不变式**：
- 12 个写死的 `/api/...` 与全部模板拼接路径逐字不变；
- `id` / `class` / 内联 `onclick` 绑定的函数名**必须全局可见**（因为 HTML 里是内联事件），
  所以 JS 用**普通 `<script>` 顺序加载**，**不改成 `type="module"`**（module 有独立作用域，
  会让内联 `onclick` 全部失效）。这是本项最容易踩的坑。
- 加载顺序必须与原内联顺序一致（全局 `state` 在前，用它的在后）。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 补丁点错位导致测试假绿 | 每步跑全量 web 测试；补丁宿主改错会立刻红 |
| 循环导入 | 依赖方向单向：`settings ← 一切`；`core_bridge ← 业务`；`api/* ← lib/*`；禁止反向 |
| 蓝图注册顺序影响路由优先级 | 蓝图内路由无通配冲突；注册顺序保持与原文出现顺序一致 |
| 前端 `type="module"` 陷阱 | 明令禁止；保持经典 script 全局作用域 |
| 入口被 shim 依赖 | `bin/ttbox-web.py` 名字与可独立执行两条，每步都验 |
