# 第三遍：关键函数逐个解读

## 3.1 `PID_Calc`（`:575`）—— 增量式 PID

```lua
local function PID_Calc(pid, reference, feedback)
    pid.lastError = pid.error
    pid.error = reference - feedback          -- ★误差 = 像素
    local pout = pid.error * pid.kp           -- 比例
    local dout = (pid.error - pid.lastError) * pid.kd  -- 微分
    pid.integral = pid.integral + pid.error * pid.ki    -- 积分
    -- 双重 clamp
    if pid.integral > pid.maxIntegral then pid.integral = pid.maxIntegral
    elseif pid.integral < -pid.maxIntegral then pid.integral = -pid.maxIntegral end
    pid.output = pout + pid.integral + dout
    -- 输出 clamp 到 ±maxOutput
end
```

**签名**：`PID_Calc(pid, reference, feedback)` → 无返回，直接改 `pid`。
**副作用**：改 `pid.error/lastError/integral/output`。
**术语**：`maxIntegral=100`（积分饱和）、`maxOutput=pid_speed_limit_value=10`（单帧最多 10 count）。

⚠ **调用方式是 `PID_Calc(pidX, fx, 0)`**（`:4664`）——`feedback` 恒为 0，
所以这实际是**纯比例-微分控制器**，微分作用在"目标位置"上而非"测量值"上。

## 3.2 `PID_CascadeCalc`（`:584`）—— 串级 PID

```lua
PID_CascadeCalc(cp, oR, oF, iF)
  PID_Calc(cp.outer, oR, oF)                -- 外环：位置误差 → 期望速度
  PID_Calc(cp.inner, cp.outer.output, iF)   -- 内环：期望速度 → 实际输出
  cp.output = cp.inner.output
```

**含义**：外环算「还要往哪走」，内环算「怎么走稳」。比单 PID 的过冲表现好。

## 3.3 ★ `calculateMovement`（`:4603`）—— 移动量计算（核心）

**签名**：`calculateMovement(at, dtt, now)` → `mx, my, fx, fy`
（返回：最终移动量、原始误差）

**主流程**：

```lua
-- ① 准星位置可被覆写（准星追踪 / 激光兜底）
local chX, chY = cfg.Centre, cfg.Centre
if crosshair_recoil_track_enabled and 已追踪 then chX,chY = 追踪到的准星坐标
if laser_fallback 按下 then chY = chY - offset          -- :4616

-- ② 误差（纯像素）
local rx,ry = at.x-chX, at.y-chY
local fx,fy = rx,ry
local mx,my = fx,fy                                      -- :4621 ★默认就是 1:1

-- ③ 分支：B 算法 / 算法5 / 算法2 / 算法4 / 算法0(线性)
if cfg.b_algo_enabled then
    -- 串级PID + I 项动态启用（近目标才开 I）
    if dtt > ki_activation_distance then 关闭 I
    elseif 延迟后 then 开启 I                              -- :4631-4648
    if dtt <= ki_dead_zone then integral *= 0.9            -- :4650 死区内积分衰减
    PID_CascadeCalc(bCascadePidX, fx, 0, st.lastMoveX)   -- :4656
    return mx, my, fx, fy
end

if mobile_algorithm==5 then mx=-adrcX:ADRC_X_Count(0,fx)  -- :4662 ADRC
elseif mobile_algorithm==2 then PID_Calc(pidX,fx,0)        -- :4664 单PID
elseif mobile_algorithm==4 then ...                        -- :4670 含压枪修正的复合
else  -- 算法0：线性
    mx = fx * aim_speed_x                                 -- :4750 ★直接乘系数
    my = fy * aim_speed_y
end
```

**★ 关键发现**：算法 0（线性）的 `mx = fx * aim_speed_x`（0.15）——
**误差和移动量是纯线性关系，没有任何 FOV / 角度 / 焦距换算**。
这就是"像素域闭环"的直接证据。

## 3.4 ★ `applyModifiers`（`:4755`）—— 输出修饰链（12 道工序）

按执行顺序：

| 序 | 修饰 | 源码 | 作用 |
|---|---|---|---|
| 1 | **死区衰减** | `:4758` | `dtt <= aim_dead` ⇒ 输出 × `aim_dead_speed`(0.3) |
| 2 | 压枪 Y 抑制 | `:4762` | 压枪中 ⇒ `my *= y_suppress_strength` |
| 3 | 自动压枪 Y 抑制 | `:4766` | 同上 |
| 4 | 按键延迟 | `:4770` | `dtt <= range` 且未超时 ⇒ **输出归零** |
| 5 | 速度波动 | `:4776` | 模拟手臂抖动的正弦波 |
| 6-8 | B 算法抑制 | `:4777-4796` | 按键触发时衰减/软锁 |
| 9 | 全局抑制 | `:4798` | `mx *= suppression_x` |
| 10 | 按键偏移抑制 | `:4799` | 同上 |

⚠ **副作用**：全部是**原地改 mx/my**（Lua 传的是值，但这里靠 return 值接）。

所以**永远不出现真正的死区**，只是减速。这和我们 TTBOX 用"余数累加"（V3 阶段 3b）不同。

## 3.6 ★ `calculateDynamicRangeValue`（`:4576`）—— 动态自瞄范围（最值得学）

```lua
local function calculateDynamicRangeValue(box_w, box_h)
    local area = (box_w or 0) * (box_h or 0)          -- 框面积 = 距离的代理量
    local minRange = cfg.dynamic_aim_range_min        -- 40
    local globalRange = cfg.user_aim_range_x         -- 100
    if area <= cfg.dynamic_aim_range_box_min then return minRange end        -- ≤200
    elseif area >= cfg.dynamic_aim_range_box_max then return globalRange end -- ≥1200
    else  -- 中间线性插值
        return minRange + (globalRange-minRange) *
               ((area-box_min)/(box_max-box_min))
    end
end
```

**物理含义**：远处小目标（面积小）用**小范围** 40px —— 只瞄很准的，
避免选到画面边缘的歪框；近处大目标用**全范围** 100px。

**在主循环的调用点**（`:5188-5190`）：
```lua
local newRange = calculateDynamicRangeValue(at.box_w, at.box_h)
cfg.effective_aim_range_x = newRange      -- ★改写全局配置
cfg.effective_aim_range_y = newRange
```

⚠ 副作用：`candidateOK`（`:804`）读的是 `cfg.effective_aim_range_x`，
所以这个"动态"实际是通过改写配置生效的——**有 1 帧延迟**（先算距离再用）。

## 3.7 `getDynamicFilterMin`（`:1806`）—— 按框面积调滤波

```lua
local area = box_w * box_h
if area <= filter_box_mid then
    ratio = min_ratio + (1-min_ratio)*(area/box_mid)    -- 小目标：ratio 小 = 强滤波
    return filter_base * ratio
else
    ratio = 1 + (max_ratio-1)*((area-box_mid)/(box_mid*2))
    return filter_base * min(ratio, max_ratio)         -- 大目标：弱滤波
end
```

**含义**：小目标抖动大 → 强滤波；大目标抖动小 → 弱滤波。

## 3.8 `getSpeedAdaptiveKpMultiplier`（`:1759`）—— 速度自适应增益

```lua
table.insert(st.speed_adaptive_kp_history, {x=at.x, y=at.y, time=now})
while #history > maxFrames do table.remove(history,1) end  -- 定长窗口
local totalDist = sqrt((last.x-first.x)^2 + (last.y-first.y)^2)
local avgSpeedPerFrame = totalDist / #history
if avgSpeedPerFrame >= threshold then return move_mult     -- 动得快→增益↑
else return static_mult end                                -- 静止→增益↓
```

**物理含义**：目标动得快时，同样的像素误差需要更大的鼠标移动才能追上 ⇒ 提高增益。

## 3.9 `applyAntiOvershoot`（`:1722`）—— 双层抗过冲

```lua
if dtt > outer_distance then
    -- 太远：不动，且若持续超阈值则重置状态机（:1727 reset_cooldown）
    return mx, my
end
if dtt <= inner_distance and inner_count < inner_frames then
    mx = mx * (1 - inner_strength/100)      -- 近距离：强衰减
    inner_count = inner_count + 1
end
if dtt <= outer_distance and outer_count < outer_frames then
    mx = mx * (1 - outer_strength/100)      -- 中距离：轻衰减
    outer_count = outer_count + 1
end
-- 两个计数器都满 → cycle_done，本轮不再衰减（避免持续削弱）
```

**设计亮点**：用**帧数门**而非纯距离门 ⇒ 靠近过程只衰减固定帧数，不会一直削弱。

## 3.10 `updateLeadPrediction2`（`:1820`）—— 带 Y 抑制的提前量

```lua
-- Y 轴抑制：|lastMoveY| 超阈值 ⇒ 提前量归零
if |lastMoveY| >= lead2_y_suppress_max then
    ySuppressFactor = 0.0; yMaxOffsetFactor = 0.0
elseif |lastMoveY| > lead2_y_suppress_min then
    local ratio = (|lastMoveY| - min)/(max - min)
    ySuppressFactor = 1 - ratio                        -- 线性抑制
end
local currentMaxOffset = lead2_max_offset * yMaxOffsetFactor
-- 积分夹在 ±currentMaxOffset
st.lead2_integral = clamp(st.lead2_integral, -currentMaxOffset, currentMaxOffset)

errorX = (at.x + lead2_integral) - chX                 -- 提前量只加 X
errorY = at.y - chY                                    -- Y 不加
```

**为什么 Y 要抑制**：纵向抖动比横向大（游戏后坐力/走路晃动），
不加抑制会让提前量把纵向误差放大 ⇒ 抖得更厉害。

## 3.11 `applyHeadBodyStable`（`:839`）—— 头身稳定

local combo1 = hasBody1 and hasHead1          -- 身体和头同时存在

# 与 TTBOX 的对照结论

## 架构层面：同构

```
BB-828:  像素误差 → PID/串级PID/ADRC → ×系数 → 修饰链 → Mouse_MoreR
TTBOX:   像素误差 → Pid1Controller(移植pid1) → ×out_gain → 修饰链 → HID注入
```

**都是像素域闭环，都是"误差 × 系数"，都没有 FOV/角度/焦距。**

## BB-828 值得学的（我们没有）

| 机制 | 收益 |
|---|---|
| **框面积 → 选靶范围**（`:4576`） | 远小目标只锁准的，近大目标放开 |
| **框面积 → 滤波强度**（`:1806`） | 小目标强滤波，减少远处抖动 |
| **速度 → Kp 双档**（`:1759`） | 动时提增益、静止时降增益 |
| **Y 轴提前量抑制**（`:1830`） | 防纵向抖动被提前量放大 |
| **抗过冲用帧数门**（`:1735`） | 靠近过程只衰减固定帧数 |

## TTBOX 更好的（不必照抄）

- `sizeScore` 量纲正确（`sqrt(面积)/size_ref`）。
- 三道量测门控（冻结 + 跳变 + 尺寸比），比 BB 的单一卡阈值严密。
