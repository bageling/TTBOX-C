## 0. 主链与判据

```
V4L2Capture → RGA → RKNN → DecodeNMS → TargetSelector → AimPointProfile落点
→ AimTracker平滑 → Pid1Controller → 输出HID
```

**真人一次瞄准移动的时间序列**：① 起步爆发 ② 接近减速 ③ **到位小幅过冲** ④ **回拉微调** ⑤ 全程微抖 ⑥遇偏差会「攒」修正量。

## ★★★ 三条根因（全部实测/核实，非推测）

### 根因 A：★ PID 没有 dt 参数 ⇒ 帧距抖动被直接放大成输出抖动

`Pid1Controller::update(double error)`（`Pid1Controller.hpp:92`）—— **签名里没有 dt**。
而同一链路上 `AimTracker::update(...,timestamp_us)`、`RecoilController::update(...,dt,...)`、
`PersonalTrajectoryShader::shape_f(...,dt_ms,...)` **全都吃时间**。**只有 PID 在裸奔。**

**主理人实测**（`pid_no_dt_probe.cpp`，目标匀速 100px/s）：
```
帧距(ms)   每帧位移(px)   Kd输出(count)   折算画面位移(px)
  6.94        0.694         -0.174           -0.113
 13.89        1.389         -0.347           -0.226
 41.67        4.167         -1.042           -0.677   ← 丢5帧，D 项放大 6 倍
```
★ **Kd 输出与帧距严格线性**。而 chain-timing 已证链路帧距在 0~3 帧周期之间抖
⇒ **帧距抖动 = 输出抖动 = 业主说的「顿一下 + 抖」**。
★ `K_i` 同理（`ki_raw` 源头 `error_diff` 无 dt 归一）⇒ **「predict 怎么调都不对劲」的根因可能在这**。

### 根因 B：板端 PID 退化成「纯 P+D」，输出**永不过冲** ⇒ 不像人

**实测**（板端 predict_x/y=0 ⇒ `ki_raw = ki_raw*predict ≡ 0` ⇒ `K_i ≡ 0`）：
符号翻转 **0 次**，从52.8px 爆发一路平滑递减到 1.9px 单调收敛。
对照 `predict=1`：翻转 2 次、有轻微过冲 ⇒ **预测项才是"像人"的来源，被默认配置掐死了**。

★ 硬证据：误差 300px 时一步 81 count，误差 14px 时一步 3 count ⇒ **大偏差/小偏差输出差 27 倍**
⇒ 系统天生「冲过头猛拉、接近时不敢动」。

### 根因 C：★「越打越慢」—— PID 输出无界，累积控制量 ∝ 误差

PID **没有任何输出饱和限幅**。`Ki` 随误差增长 ⇒ **偏得越多收得越慢**。
★ 两条独立路径同结论：静态分析（Ki ∝ 误差、无界）+ 实测（Ki 稳态趋近 `1−|err|/50`，误差越大这帧挪得越少）。
★ 这是**「跟手度不足」的物理主因，比调 kp更本质**。

## ★★ 时序层：输出在时间上不连续的 6 处（chain-timing，逐条 file:line）

1. **PID reset 后 kp_gain 从 0 爬 528ms** ⇒ 输出斜坡。★ 真人按键即满速。
2. **Kd 在丢帧瞬间翻倍→ 反向刹车过冲**（根因 A）。
3. **压枪 `step_px = rate×dt`，丢帧时单帧注入 5.9 倍**（`RecoilController.hpp:194`，无 clamp）。
4. **热键按下瞬间亚像素余额清零**（`AimThread.cpp:158-161`）—— ★ 与「余数永不丢」新语义**自相矛盾**。
5. **准星找色 interval=10 帧 ⇒ 急停判据最多陈旧 69ms**。
6. **AimThread 4ms 盲轮询与发布节奏无同步 ⇒ 0~4ms 随机相位**（`AimThread.cpp:981`）。

## ★★ 延迟预算：这条链路**没有一处是恒定延迟**

- 板端实测 e2e ≈ 48.9ms（≈7 帧@144fps）。
- 代码可算的纯结构性等待 ≈ 9.4ms（分段 A 均 1 帧 + 分段 B 均 2ms + usbproxy 均 0.5ms）。
- ★ **恒定部分加起来不足总延迟 5%**；其余是量化台阶（0~3 帧取模分配）+ NPU 抢占 + usbproxy 1ms 锯齿。

## ★★ 参数「名字骗人」清单

| 参数 | 面板标签 | 实际作用 | 调错后果 |
|---|---|---|---|
| `smooth` | 「缓冲」 | **削弱倍率** `10000−smooth` | 调"更稳"反而输出砍到 1/10 |
| `predict` | 「预判」 | **输出自激励前馈** | 当"预测"调会发散（无上限校验，面板允许 10，边界 1.5~2.5） |
| `rate` | 「跟随速度」 | `kp_gain`爬升速率 | 调大 = 更凶 |
| `output_deadzone` | 「小于它就不动」 | **余数累积**，决定"多久发一次" | 余数一直保留 |
| — | — | **前馈:反馈 = 90:1**（`K_i` 恒 9000 不受 smooth 管） | 无旋钮可调 |

★ `smooth=0` ⇒ 整个软限幅被 `if(smooth)` 跳过 ⇒ **输出暴涨 100 倍**，滑杆 0 就在最左边。
