## §1 命名

| 对象 | 规则 | 例 |
|---|---|---|
| C++ 目录/文件 | 大驼峰，扩展名 `.hpp` / `.cpp` | `TargetSelector.hpp` |
| C++ 类/结构 | 大驼峰 | `CoreRuntime` |
| C++ 函数/变量 | 小驼峰 | `resolveHeadBox` |
| C++ 成员 | 尾下划线 | `config_` |
| C++ 常量 | `k` + 大驼峰 | `kCoreVersion`（沿用现状） |
| Python 模块/文件 | 小写下划线 | `cloud_session.py` |
| Python 函数/变量 | 小写下划线 | `apply_factory_config` |
| Python 常量 | 全大写下划线 | `DEFAULT_TIMEOUT` |
| 配置键 | 小写下划线 | `npu_core_masks` |
| 脚本 | 小写下划线 + 类型前缀 | `ttbox_release_install.sh` |

**禁止**：拼音命名；无意义缩写（允许的通用缩写仅：`cfg` `ctx` `impl` `buf` `src` `dst` `idx` `cnt` `tmp` `id`）；单字母变量（循环变量 `i/j/k` 除外）。

**改名要求**：Q17 的 `worker_cores` 实为 NPU core_mask，统一改为 `npu_core_masks`，并在出厂配置与代码两侧同改。

## §2 文本与格式

- 编码 **UTF-8 无 BOM**。
- 行尾：**新增文件一律 LF**。`core/` 存量 CRLF 文件在首次修改前先归一化为 LF，改完写回 LF。
- 缩进：C++ 4 空格；Python 4 空格；JSON 2 空格。
- 文件末尾保留单个换行。
- 大括号：C++ 用 Allman 或 K&R 皆可，**同一目录内必须一致**（以该目录内占比最高的既有风格为准）。
- 注释写「为什么」，不写「是什么」。禁止注释掉的死代码留在文件里（要用就留，不用就删）。
- 自动生成文件必须在**文件头 5 行内**标注 `@generated` + 生成脚本路径 + 生成命令。

## §4 文件行数

### 4.1 计数口径（**唯一口径，不得争议**）

- 计数对象：**物理行数**，含空行、注释、大括号。
- 计数命令（无末尾换行时 `wc -l` 会少算，故统一用）：
  ```bash
  awk 'END{print NR}' <file>
  ```
- 不计入：文件头带 `@generated` 标记的自动生成文件（须同时给出生成脚本路径）。

### 4.2 规则

| 情形 | 规则 |
|---|---|
| **新增文件** | **≤ 300 行（硬线）**，超限即门禁失败 |
| **存量文件** | 首次可**原样搬**，不改不加；搬完后进入《超长文件登记表》 |
| **存量文件被修改** | **行数增幅 ≤ 20%**，且不得跨过下一个 100 的整数位（防止大文件继续膨胀） |
| **生成文件** | 免检，但必须标 `@generated` |

### 4.3 《超长文件登记表》字段

`文件路径 | 当前行数 | 归属进程 | 超长原因 | 拆分计划（拆成哪几个） | 到期日 | 责任人`

**到期未拆即视为门禁失败。** 延期需 PM 逐次批准。

现状已知超长文件（首批登记）：`plugins/web/bin/ttbox-web.py` 6,087｜`plugins/web/templates/index.html` 13,406｜`core/src/app/Application.cpp` 2,265｜`core/src/ipc/IpcServer.cpp` 1,212｜`core/src/rknn/DecodeNMS.cpp` 899。

## §5 日志

### 5.1 分级

`FATAL > ERROR > WARN > INFO > DEBUG`

- **正式版**：允许输出 FATAL/ERROR/WARN/INFO；DEBUG 由编译期开关关闭。
- **测试版**：DEBUG 全开 + 保留崩溃证据（`LimitCORE`、不剥调试符号）。
- 默认级别：INFO。级别必须可在配置里调，不用重编译。

### 5.2 分流（落实「少写卡」+「能导出」的折中）

| 级别 | 去向 | 落盘 |
|---|---|---|
| FATAL / ERROR | 直接写 `/var/log/ttbox/` | 同步 `fsync` |
| 客户操作（启动/停止/换模型/改参数/导出/恢复出厂） | 写 `/var/log/ttbox/operation.log` | 同步 |
| WARN / INFO | tmpfs 内存环形缓冲 | 每 5 分钟批量落盘一次 |
| DEBUG | 仅内存 | 测试版可落盘 |

- 滚动：**12 小时清理一次**，只留重要操作与报错（对齐 `#64`）。
- 单文件上限 8 MB，超限即轮转，保留 3 个历史文件。
- `/var/log/ttbox/` 目前为空目录（Q29），本阶段必须转为真实使用。

### 5.3 格式

```
<ISO8601 本地时间> <LEVEL> <module> <message> k1=v1 k2=v2
2026-10-01T12:03:44+08:00 ERROR capture v4l2 ioctl failed fd=7 errno=25
```

- `module` 用文件或逻辑模块短名，禁止写类名全称。
- 键值对便于自动解析，禁止把变量塞进 message 里。
- **禁止**：密码明文、卡密全文（最多留后 4 位）、私钥、账号密码、客户上传模型的原始文件名。

### 5.4 禁止的日志出口

- 禁止用 `std::cout` / `print` 当日志（CLI 交互输出除外）。
- 允许同时输出到 journald，但**必须**同时有文件 sink —— journald 在板端会滚动丢失。

## §6 错误处理（禁止空 catch）

### 6.1 C++

- **禁止** `catch (...) {}`、空 `catch (const std::exception&) {}`。
- 最小形态：
  ```cpp
  } catch (const std::exception& e) {
      LOG_ERROR("model", "load failed", {{"path", p}, {"what", e.what()}});
      return Status::Error;
  }
  ```
- 确需忽略时必须显式标注并计数：
  ```cpp
  } catch (...) {  // intentionally-ignored: 风扇设转失败不影响启动 ref:Q27
      ++ignored_fan_errors_;
  }
  ```
- 禁止 `catch` 后 `return` 成功状态。
- 禁止用异常做正常控制流。

### 6.2 Python

- **禁止**裸 `except:`、**禁止** `except ...: pass`。
- 最小形态：`except Exception as e: log.error("...", exc_info=True); raise` 或返回明确错误。
- 需要忽略时同样需 `# intentionally-ignored: <原因> ref:<编号>` 注释。

### 6.3 假成功（Q22）

- 接口返回成功前必须确认动作确实执行。禁止「返回 200 但什么都没做」。
- 现状两处必修：`ttbox-web.py:3487-3492`、`:214-226`。

### 6.4 现状整改量

审计 §15.2：**C++ 4 处空 catch + Python 12 处 `except: pass`**，本阶段清零，门禁脚本纳入扫描。

## §7 路径与配置

- C++ 路径单点真源：**`core/src/common/Paths.hpp`**（设计正确，继续沿用）。
- Python 路径单点真源：**`plugins/web/lib/paths.py`**。
- **板端绝对路径字面量只允许出现在上述两处。**其余任何位置出现 `/opt/ttbox`、`/var/lib/ttbox`、`/etc/ttbox`、`/run/ttbox` 一律门禁失败。
- 现状必修：`ttbox-web.py:3824/3854/4765`（Q20）。
- 客户数据统一落 **`/var/lib/ttbox`**（老板拍板）；`/opt/ttbox/{config,presets}` 内属客户数据的部分迁移，其余降级为只读出厂默认值。→ 解决数据目录分裂（Q23 / 审计 §22.3）。
- 编译期默认配置 `config/default.json` 与出货 `deploy/config/{default.json.prod,00-factory.json}` 必须**同值**，门禁断言（R6）。
- 配置键变更必须同步：schema + 出厂配置 + 迁移说明（若该键属"客户会改"的，需给出升级后处理口径）。
- **禁止**把密钥、口令、卡密种子写进代码或配置；一律走运行时读取。

## §8 预留接口登记制

### 8.1 代码标注格式

```cpp
// RESERVED(purpose=云端下发模型, planned=P3, expiry=2027-03-01, ticket=T-014)
```
```python
# RESERVED(purpose=低帧预览独立进程, planned=P2, expiry=2027-03-01, ticket=T-018)
```

### 8.2 《预留接口登记表》字段

`编号 | 文件:行 | 用途 | 计划使用阶段 | 到期日 | 责任人 | 状态(活跃/已转正/已删除)`

### 8.3 规则

- 未登记 = 门禁失败。
- 登记无 `expiry` = 门禁失败。
- **到期日未使用即删除**；延期需 PM 逐次批准并更新到期日。
- 转正后状态改「已转正」，允许撤掉 `RESERVED` 标记。
- 现存"研发放行模式"（心跳豁免开关，见《第一阶段执行清单》T1-1）按本制度登记，到期日 = 第二阶段云端联调完成日。

### 8.4 边界

预留接口**只允许是接口/入口/配置项**，不允许预留"半截实现"和"不可达的大段代码"。后者既不是预留，也不是死代码，是未完成品——不得入库。

## §9 提交与变更

- **一个 bug 一个提交**，一个提交只做一件事。
- 提交信息格式：
  ```
  [P1] fix(capture): 采集层改用 RGA 前置 crop，绕开不生效的硬件选择 ref:Q4
  [P1] refactor(core): 原样搬 capture 段，行为等价
  [P1] cleanup(web): 删除 api_v1.py 与 framework_api.py ref:Q11
  ```
- 类型白名单：`fix` / `refactor` / `cleanup` / `docs` / `build` / `test` / `chore`。
- **禁止**一次提交混多种类型、禁止夹带无关格式化。
- 每笔 `fix` 提交必须附《旧版行为 vs 新版行为对照表》条目（对齐 `#165`）。
- **不主动** `git commit` / `push` / 改远端，除非明确要求。
- 删目录禁止用 `git rm -r`（会连整棵树），用 `rm -f <files>` + `git add -A <dir>`。

## §10 硬红线

1. **禁打补丁直写板端运行树**。只走：改 → 提交 → 构建 → 打包 → 发布 → OTA。
2. **禁在板端手改文件**。板端配置只走 IPC `SET_CONFIG` 或 web `PUT /api/config`。
3. **禁新增第三方依赖 / 框架**（除非老板批准）。`core/third_party/` 只读，禁止修改。
4. **删任何东西前先确认它不是合规标识 / 溯源字段 / 授权信息**。
5. **禁把测试开关、调试符号、明文程序、mock 桩带进正式包**。
6. **禁假成功**（§6.3）。
7. **禁在日志里打印敏感信息**（§5.3）。
8. **构建向量顺序固定**：`-DCMAKE_SYSROOT` 必须写在 `-DCMAKE_TOOLCHAIN_FILE` **之前**（顺序反了出货向量哈希会变）。
9. **禁制品入库**：`__pycache__`、`*.pyc`、`*.o`、`*.exe`、构建日志。
10. **禁绕过授权链路**：`core/src/auth/` 与验签相关改动必须单独报备。

## §11 门禁脚本（可机械校验项）

一条命令跑完，全部通过才允许进入下一批。

| 编号 | 检查 | 失败条件 |
|---|---|---|
| G1 | 行数 | 新增文件 > 300；存量未登记文件增幅 > 20% |
| G2 | 空处理 | 命中 `catch(...){}` / `except: pass` / 裸 `except:` |
| G3 | 硬编码路径 | 源码出现 `/opt/ttbox` `/var/lib/ttbox` `/etc/ttbox` `/run/ttbox` 字面量（`Paths.hpp` / `paths.py` 除外） |
| G4 | 预留登记 | 源码 `RESERVED` 标记 ↔ 登记表不一致；缺 expiry |
| G5 | 版本真源 | `core/CMakeLists.txt` 的 `project(... VERSION ...)` ≠ `kCoreVersion` |
| G6 | 测试 | ctest 41 + pytest 39/61/476（合计 576）非全绿 |
| G7 | 制品 | 仓库出现 `__pycache__` / `*.pyc` / `*.exe` / 构建日志 |
| G8 | 大小写路径 | 文件名大小写冲突或改动他人目录归属 |

> G6 运行环境：宿主构建目录必须为 **ASCII 路径**（中文路径下 ctest 恒少 2 例假失败）。交叉编译走 WSL，构建产物路径与命令写入 `docs/build/`。
