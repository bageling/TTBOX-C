## 附加三：批次 1.4 日志分级与分流骨架（2026-10-01 18:xx）

**范围**：只落地《代码书写规矩·技术版》§5 的**骨架**（分级 / 分流 / 格式 / 落盘），
不动任何既有业务逻辑、不加新功能。这是"搬核心链路"之前的地基件 —— 后面所有模块
都要按这套口径打日志，先把口径本身立起来。

### 落成的口径

- **§5.1 分级**：`FATAL > ERROR > WARN > INFO > DEBUG`，`kOff` 只作关闭哨兵。
  默认 INFO；**级别可配置、不重编译**（core `--log-level` / 环境变量 `TTBOX_LOG_LEVEL`）。
- **§5.2 分流**（少写卡 #64）：
  - FATAL/ERROR → `ttbox-error.log`，**直写 + fsync**，内容永不被 12h 清理过滤；
  - WARN/INFO → 内存环形缓冲（上限 4096 行），**每 5 分钟批量落盘** `ttbox.log`；
  - DEBUG → **只进内存，不落盘**；
  - 客户操作 → `operation.log`，**同步写**，永不丢；
  - 单文件 8MB 轮转、保留 3 个历史；12 小时清理一次（只轮转全量流水，不动 error/operation）。
- **§5.3 格式**：`<ISO8601 本地时间> <LEVEL> <module> <message> k1=v1 at=<file>:<line>`。
  时间戳含时区（`+08:00`）、无毫秒；module 由 `__FILE__` 派生短名（禁类名全称）；
  kv 走独立通道、**不塞进 message**。
- **§5.4 禁 `std::cout`/`print` 当日志**：core 保留 ConsoleSink（journalctl 是板端第一手
  现场入口）+ FileSink；web 挂 StreamHandler + FileHandler，**两边都有文件 sink**。

### 文件分工实现"12 小时清理"

不读写重写任何文件内容，靠**三文件分工**：

| 文件 | 内容 | 保留机制 |
|---|---|---|
| `ttbox.log` | 全量流水 | 12h 轮转 + 8MB×3 历史，旧的自然消失 |
| `ttbox-error.log` | 只 FATAL/ERROR | 内容永不过滤 ⇒「报错」永在 |
| `operation.log` | 客户操作 | 同步写 ⇒「重要操作」永在 |

### 三处设计决定（都写进了代码注释）

1. **web 的日志目录不挂 `TTBOX_PREFIX`**：日志属 `/var/log`，不随版本目录走 ——
   否则 OTA 换一次版本就把历史日志换掉。
2. **FileSink 降级安全**：目录不存在/不可写 ⇒ `usable()==false`，此后全部 write 静默
   丢弃，**不抛不 abort**（"日志设施挂了不许拖垮启动"）。
3. **只记改动型 IPC 命令**：读型（PING / GET_* / MODEL_LIST / MODEL_VALIDATE）不记 ——
   面板每秒轮询，记了会把 `operation.log` 刷爆。
