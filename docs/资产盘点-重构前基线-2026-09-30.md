1. **`plugins/web/templates/index.html`（13,406 行单文件）** — CSS 5,188 + HTML 1,000 + JS 7,200 全挤一个文件，301 个 id。建议拆为 `index.css` / 分页模板 / 模块化 JS。**测试面 467 用例可做安全网。**
2. **`plugins/web/bin/ttbox-web.py`（5,958 行）** — 60+ 路由单文件，建议按域拆 Blueprint（config / models / license / motion / branding / update）。
3. **`core/src/app/Application.cpp`（2,265 行）** — 总装逻辑单文件。
4. **`core/src/ipc/IpcServer.cpp`（1,212 行）** — 协议分发可拆 handler。
5. **空目录清理**：`core/src/controller/`、`core/src/coordinate/` 均为空目录。
6. **构建产物污染**：`core/build-*`（51M）与散落 `*.o/*.d/*.obj/*.exe/*.make` 位于源码树内。
7. **文档归档**：66 份 `RELEASE_BUILD-*.md` 可滚动合并。
8. **重复资产**：`tools/ota/keys/ttbox-ota-2026b.pub` 与 `deploy/keys/ttbox-ota-2026b.pub`；两个 dtb 副本（`deploy/dtb/` 与 `image/factory/`）。
9. **两套版本谱系并存**：`dist/` 内 `1.5.x` 与 `V1.0.x` 混放；`deploy/ota-out/1.5.30~34` 是旧谱系残留。
10. **README 过期**：版本号停在 V1.0.01。

### 16.2 风险红线（重构不得触碰）

- 出货向量口径：交叉构建必须保持 `configure_args` 顺序（`SYSROOT` 在前），否则 `vector_hash` 变化（`65802e9d…` → `cd79d81d…`）。
- 宿主 ctest 必须在 ASCII 路径运行，中文路径恒产生 2 例假失败。
- `plugins/web` 的 467 个测试是行为契约，重构不得为「让测试过」而改测试预期。
- `usbproxy/usb-proxy` 预编译二进制与 `.sha256` 是交付物，非源码产物。
- `deploy/keys/`、`tools/*/keys/` 的 `.pub` 是**授权/溯源标识**，不是可清理的旧值。

## 17. 待确认缺口（重构范围锁定用）

1. **「框架」指哪一层？** 三种可能，工作量差异巨大：
   - A. `plugins/web/` 前端+后端单体拆分（最大痛点，风险可控，测试最全）
   - B. `framework/` + `platform/` + `plugins/` 三层 Python 架构重新分层（架构级）
   - C. `core/` C++ 核心模块重整（耦合最深，出货风险最高）
2. **是否允许改动已出货的对外契约？** 包括 `plugin.json` 的 `api_version`、IPC JSON 协议、`/api/*` 路由路径。
3. **验收口径**：以「测试全绿 + 向量 hash 不变」为准，还是另有交付验收？
4. **是否顺带清理构建产物与归档**（`.archive-2026-09-23` 349M、`core/build-*` 51M）？此动作不可逆，需单独确认。
