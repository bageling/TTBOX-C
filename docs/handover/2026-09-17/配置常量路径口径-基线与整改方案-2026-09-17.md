## 〇、复核结论（先看这里）

1. 侦察数字**大部属实**，但 **3 处误报**必须纠正（详见 §附录B）：`端口 5000 ×20` 实为测试时间戳/微秒数，**全仓无 5000 端口**；`SaaS 8080/8081` **全仓 0 命中**；`10015` 仅 1 处且是云端回调端口常量、非"SSH 10015"。

## §1 口径基线（唯一权威定义表）

> 本节是**可判定规则**：工程师照做、QA 照测、门禁照断。凡与本节冲突的现状一律进 §2。
> 术语：**真源（SSOT）= 该事实的唯一写入点**；**投影**= 从真源派生/读取、绝不独立赋值。

### A. 路径口径

| 编号 | 规则（可判定） |
|---|---|
| **A-PATH-1** | **C++ 运行根**唯一来源 = CMake `-DTTBOX_PROJECT_ROOT`（**编译期常量**）。派生根下资源**必须**写成 `std::string(TTBOX_PROJECT_ROOT) + "/<sub>"`。**禁止**在 C++ 源码里另写 `/opt/ttbox` 字面量当运行根。 |
| **A-PATH-2** | **C++ 运行期可变路径**（IPC socket 等）取「**CLI 参数 > 环境变量 > 编译期/头文件默认**」三级链；三级默认值**必须来自单一头文件常量**，不得在 .cpp 内散写。 |
| **A-PATH-3** | **Python 自身位置**用 `Path(__file__).resolve().parents[N]`（相对派生），**禁止**硬编码 `/opt/ttbox/...` 绝对路径进 `sys.path`；跨包注入只在**插件启动脚本头部一次性**完成（`sys.path.append` 仓库根 + `sys.path.insert(0, plugin_root)`），业务路径不得二次改写 `sys.path`。 |
| **A-PATH-4** | **shell 根前缀**一律参数化：`TTBOX_PREFIX`（默认 `/opt/ttbox`）/ `TTBOX_ETC`（`/etc/ttbox`）/ `TTBOX_RUN`（`/run/ttbox`）/ `TTBOX_REPO`（仓库根）。仓库根由 `dirname "${BASH_SOURCE[0]}"/..` 反推（**C2 硬约束**：`scripts/` 不得外移）。 |
| **A-PATH-5** | **同一路径字面量全仓单点定义**：`/run/ttbox/core.sock`、`/run/ttbox-mouse-passthrough/{cmd,event}.sock`、`/etc/ttbox/license.key` 各只允许**一处**定义 + 其余引用/派生。跨语言（C++/Py/sh）**打不通 include 时**，以**登记表 + 门禁脚本**保证同值（登记表见 §3 T-E）。 |
| **A-PATH-6** | **禁止**：注释/文档声称某路径"仍然生效"而代码已删除（装饰性误导，见 `ttbox-core.service` 已删的 `LD_LIBRARY_PATH` 注释是**正例**——它明确写了【已删除】）；**禁止**构建机绝对路径进产物（C1/A4②`strings` 门禁）。 |

### B. 常量口径

| 编号 | 规则 |
|---|---|
| **B-CONST-1** | **单点定义**：C++ 常量集中在头（如 `core/src/common/` 或对应模块头）；Python 集中在模块顶层常量；shell 集中在脚本头部 `readonly` 段。同一常量**只允许一处赋值**。 |
| **B-CONST-2** | **跨语言同值常量**（如 socket 默认、预览帧率上限、心跳间隔）必须有**唯一 C++ 头** + Python/shell 同名镜像 + **登记表** + **同值门禁测试**（防漂移）。 |
| **B-CONST-3** | **版本号语义分离**：core 版本（`version.hpp::kCoreVersion`）、对外 app 版本（web `APP_VERSION`）、release 版本（`TTBOX_RELEASE_VERSION`）**三个不同事实**必须**不同名**，**禁止**多处硬编码同一字符串。 |
| **B-CONST-4** | **时间/阈值常量**（心跳 `60/180`、EDID `settle/timeout/attempts`、重试/超时）**单点定义**；调用方只引用，不得各写一份。 |
| **B-CONST-5** | **禁止**：`x or DEFAULT` 掩盖、`try/except` 吞错后回兜底常量、复制粘贴常量、同一常量两处各写一个默认值。 |

### C. 配置口径

| 编号 | 规则 |
|---|---|
| **C-CFG-1** | **运行期配置真源唯一** = 板端 `/etc/ttbox/config.d/`（分层：`00-factory.json` 只读基线 ← `10-device.json` 客户层，按文件名升序深合并）。**写回目标唯一** = `config.d/10-device.json`。 |
| **C-CFG-2** | **读取优先级链**（唯一）：`--config <path>` > `TTBOX_CONFIG` > 编译期默认（`kDefaultConfigPath = TTBOX_PROJECT_ROOT "/config/default.json"`，**仅本机开发兜底**）。**生效路径必须在服务启动时显式给出**（systemd 传 `--config` 或 `TTBOX_CONFIG`），**禁止**让 Web 与 Core 各自独立解析。 |
| **C-CFG-3** | **单一写入者**：**运行时配置的写回只能由 Core 执行**（经 `SET_CONFIG` IPC → `ConfigManager::persist`）。**Web/任何 Python 侧禁止直接读写配置文件**；需要读配置一律走 Core IPC（`GET_CONFIG`）。 |
| **C-CFG-4** | **默认值单一真源 = `deploy/config/00-factory.json`**。C++ `ConfigManager::get_*(key, def)` 的 `def` **不得**成为第二个默认真源——要么与 00-factory 一致且有测试断言，要么改为**读不到即 fail-fast**。 |
| **C-CFG-5** | **模板与基线分离且不冲突**：`config/default.json` 只能定位为"**本机开发样例**"，**禁止**与 `deploy/config/00-factory.json` 出现同键不同值还并存（见 §2 V-03）。出厂基线只有 `deploy/config/`。 |

### D. env 变量口径

| 编号 | 规则 |
|---|---|
| **D-ENV-1** | 命名前缀统一 `TTBOX_`；**按作用域分类**：**BUILD**（CMake/toolchain/门禁，编译期消费）/ **RUNTIME**（进程启动后读）/ **TEST**（仅测试/自测脚本）。 |
| **D-ENV-2** | **RUNTIME 变量必须登记 allowlist**（名 / 类型 / 默认 / 真源 / 覆盖语义 / 作用域），未登记即视为违规。 |
| **D-ENV-3** | **同义不同名必须归一**：`TTBOX_MODELS_ROOT` ≡ `TTBOX_MODEL_ROOT`；`TTBOX_CONFIG` ≡ `TTBOX_CONFIG_PATH`；`TTBOX_WEB_PORT` ≡ `TTBOX_DEFAULT_WEB_PORT` ≡ `TTBOX_PORT`。保留 1 个名，其余**删除**（不保留兼容读）。 |
| **D-ENV-4** | RUNTIME env **只在启动时归一为内部变量**（如 core 的 `env_or_empty` 模式），业务路径**禁止**重复 `getenv`/`os.environ.get`。 |
| **D-ENV-5** | **禁止**：`X or Y` 形式的双名兼容读（= 打补丁）；**禁止** env 名与常量名同名却语义不同。 |

## §3 无补丁整改方案（按依赖排序）

> 原则：**先建真源，再删散落，后加门禁**。每条标注**依赖**、**文件清单**、**根治手法**，并**显式声明"禁止用什么补丁手法绕"**。
> 若某条只能"半根治"，写明残余风险。

### T-A 建立口径登记表（**前置，无依赖**）
- **目标**：把 §1 的规则落成一张**机器可校验的登记表**：`docs/protocols/config-path-env-registry.md`（新）——列全部 RUNTIME `TTBOX_*`（名/类型/默认/真源/覆盖语义/作用域）+ 全部"跨语言同值常量"（socket 默认、预览 fps 上限、心跳间隔…）。
- **文件**：`docs/protocols/config-path-env-registry.md`（新增）；`docs/README.md`（登记入口）。
- **根治手法**：登记表即真源清单；后续 T-C/T-D/T-E 一律"先登记后改码"。
- **禁止**：禁止把登记表写成"现状描述"而不写"目标值"（否则等于给漂移背书）。
- **依赖**：无。

### T-B 配置真源归一（**依赖 T-A**）
- **目标**：落实 C-CFG-1/2/3/4/5。
- **文件**：`plugins/web/bin/ttbox-web.py`（删 `_config_file_path/_load_config_file/_save_runtime_profile_to_file`，改走 IPC）；`deploy/systemd/ttbox-core.service`（确保 `--config /etc/ttbox/config.d` 为唯一运行配置入口）；`config/default.json`（降级为开发样例、与 00-factory 对齐键集或改名）；`deploy/config/00-factory.json`（唯一出厂默认真源，补 `cpu_min_freq_percent` 等缺失键）；`core/src/app/Application.cpp`（`:208/:492//:86` 兜底默认指向单点常量，或改 fail-fast）。
- **根治手法**：**Web 不再碰配置文件**（读写全经 IPC）；默认值单一真源 = 00-factory；`config/default.json` 与出厂基线**键集一致或不同名**。
- **禁止**：❌ 让 Web 通过 `TTBOX_CONFIG` 指向 `config.d` 目录来"对齐"（那是**第二个解析器**，非根治，且 `ConfigManager` 目录分层的 persist 语义在 Web 无法保证）；❌ 用"两处都改一遍"掩盖 V-01。
- **残余风险（半根治声明）**：让 Web 只读 IPC 后，**Core 不可达时 Web 面板将无法展示配置**（原先靠直读磁盘兜底）。这是**有意**的 fail-loud；需在 UI 明示"Core 离线"。
- **依赖**：T-A。
