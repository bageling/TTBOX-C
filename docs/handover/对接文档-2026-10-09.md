## 0. 先拿到这些才能开工（凭据与访问）

⚠ **本仓库是公开的，所以凭据一律不入库**。以下东西必须**向项目所有者单独索要**：

| 需要什么 | 用途 |

★ **签名私钥是 Ed25519，不是 RSA**——`openssl rsa -check` 会误报 `Not an RSA key`，
真口令错看 `bad decrypt`，验证要用 `openssl pkey`。

## 1. 十分钟认识这个项目

**一句话**：TTBOX 是一个**纯视觉 AI 自瞄盒子**（RK3588 arm64，香橙派 5 Plus）。
HDMI-RX 采集游戏画面 → NPU 推理找人 → 选一个目标 → 算该挪多少 → 通过 USB 代理把鼠标位移**搭车**物理鼠标报告发给被控电脑。

**硬件接线**（详见根 README §一）：

```
[被控电脑] ←USB数据线→ [盒子 USB-C/device口]      ← 对主机伪装成鼠标
                        [盒子 USB-A/host口] ←USB鼠标→ 物理鼠标插这里（必须插，否则整链路不动）
[游戏机/电脑] —HDMI→ [盒子 HDMI-IN]
```

**软件分层**：

| 层 | 目录 | 说明 |
|---|---|---|
| 核心引擎 | `core/`（C++17，~21 万行） | 采集→RGA→RKNN→解码→选靶→PID→输出，7 段主链 |
| USB 代理 | `usbproxy/`（C++ + Lua） | 物理鼠标透传 + AI 位移搭车；**预编译 ELF 入 git**（见 §5.2） |
| Web 面板 | `plugins/web/`（C++ 后端 + 静态前端） | 面板已由 C++ `ttbox_web` 伺服（V1.0.47 起） |
| 出货物 | `deploy/` `scripts/` `image/` | 打包清单 / 构建发布脚本 / 出厂镜像烘焙 |

## 2. 开发环境（这台机器的特殊配置）

⚠ **关键：本机 host 测试必须走软链，否则 ctest 会假失败**（中文路径问题）：

| 软链 | 指向 | 用途 |
|---|---|---|
| `C:/ttbox-local` | 本仓库 | **core 构建与测试唯一入口**（`build-ascii`、交叉构建目录都在这下面） |
| `C:/ttbox-gate` | 本仓库 | 口径门禁入口 |

**必备工具位置**（`PATH` 要含）：

```
/c/msys64/ucrt64/bin          ← ★ core ctest 依赖，漏了报 0xc0000135
C:/Users/Administrator/bin/   ← plink / pscp（原生 exe，不在 PortableGit 里）
```

| 工具 | 位置/说明 |
|---|---|
| Python | `.workbuddy/binaries/python/envs/default/Scripts/python.exe` |
| Node | `.workbuddy/binaries/node/versions/22.22.2-6/node.exe` |

| 交叉构建目录 | **必须 `build-aarch64-t148`**（`t114` 缺 sysroot 会 FATAL） |

## 3. 日常开发循环（改 → 测 → 出货）

### 3.1 改代码

源码真源 = 本仓库。**规矩**：`core/` 改动走 git；配置改动走 `deploy/config/` 或 `image/factory/`。

### 3.2 本地测试（三道，全绿才继续）

```bash
# ① 口径门禁（中文路径会假 FAIL，务必走软链）
cd /c/ttbox-gate && bash scripts/ttbox_conventions_gate.sh        # 判据 RESULT: PASS

# ② C++ 单测
cd /c/ttbox-local/core/build-ascii && ctest --output-on-failure    # 判据 0 failed（当前 41 个）

# ③ Python 结构守卫（testpaths 已配，直接跑）
cd 仓库根 && python -m pytest -q                                    # 判据 0 failed
python docs/check_links.py                                          # 判据 broken_count=0
```

⚠ **假绿盲区**：本机 host **没有** jpeg/opencv/rga/rknn 等库，以下文件**根本不参与本机编译**，
改了它们 ctest 全绿**说明不了任何事**：
`PreviewModule` / `RKNNEngine` / `WorkerPool` / `V4L2Capture` / `TtboxLicenseClient`。
同类：`usbproxy/*.cpp` 本机零覆盖。**这些必须走板端口径或交叉编译验证。**

### 3.3 提交（必须在交叉编译之前）

```bash
git add -A -- <改动的路径>          # ★ 禁 git rm（本项目会删整棵树）；删文件用 rm -f + git add
git commit -m "V1.0.64：<做了什么>"
```

### 3.4 WSL 交叉编译（出货唯一入口）

★ 脚本**必须写到 Windows 侧**再让 WSL 执行（写 Git-Bash `/tmp` 它看不见），
调 `wsl.exe` 前**必须** `export MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*'`（否则路径被改写报 No such file）：

```bash
WSLC=/c/Users/Administrator/AppData/Local/Temp/wsl_build.sh
cat > "$WSLC" <<'EOF'
#!/bin/bash
set -o pipefail
cd /mnt/c/ttbox-local || exit 1
TTBOX_BUILD_DIR=build-aarch64-t148 TTBOX_RELEASE_VERIFY_USBPROXY_REBUILD=1 \
bash scripts/ttbox_build_release.sh \
  -DCMAKE_TOOLCHAIN_FILE=deploy/cmake/toolchain-aarch64.cmake \
  -DCMAKE_SYSROOT=/root/sysroot -DTTBOX_PROJECT_ROOT=/opt/ttbox \
  -DTTBOX_CROSS_AARCH64=ON -DCMAKE_BUILD_TYPE=Release 2>&1
echo "BUILD_RC=$?"
EOF
sed -i 's/\r$//' "$WSLC"
export MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*'
/c/Windows/System32/wsl.exe -d Ubuntu-22.04 -- bash -s < "$WSLC" 2>&1 | tail -60
```

**判据 `BUILD_RC=0`**。门禁是 fail-closed（缺库直接 FATAL，跳不过）。
留档自动写 `docs/build/release-records/`（白名单，会入库）。

### 3.5 打包签名 + 上传入库

```bash
# 打包（WSL 内执行；out_dir 用持久路径别用 /tmp）
bash scripts/ttbox_pack_ota.sh build-aarch64-t148 dist \
  --priv <私钥路径> --password-file <口令文件> --key-id <key-id>
# 产出 dist/ttbox-<ver>.ota.tgz + .sign.json

# 上传入库（publish=0 不激活）
注意：bridge 只在服务器本机 127.0.0.1 监听，外网无入口
```

**★ 切 latest（publish=1 / set-latest）必须所有者明确指令**：
一执行，**所有在线盒子下次心跳立刻 OTA，已升级的板子回不去**。

## 4. 硬约束（违反即事故）

1. **本仓库是唯一源码真源**。不在板端/服务器运行树里改任何东西（**禁打补丁**）。
2. **前一步没 PASS 不许进下一步**。无证据不写 PASS；不能执行的写 `NOT EXECUTED` + 原因。
3. **改了 core 先 commit 再交叉编译**（否则留档的 commit/sha256 不自洽）。
4. **切 latest 必须业主批准**。智能体最多做到"入库 publish=0"。
5. **禁 `git rm`**（会删整棵树）；删文件用 `rm -f` + `git add -A -- <path>`。
6. 修改板端配置只走 IPC `SET_CONFIG` / web `PUT /api/config`，**不直写运行树**。
7. `core/` 不许改 `deploy/config/` 之外的东西影响出货清单（清单 = 出货树的全部来源）。
8. **推送前必扫凭据**（本仓库 public）：正对照 + 负扫描，见 §6。

## 5. 接手必读：踩坑清单（按"最容易翻车"排序）

### 5.1 ★★ 仓库里有两个同名 `10-device.json`，内容差 23 倍

| 文件 | 用途 |
|---|---|
| `image/factory/10-device.json`（`mouse` 段 **46 键**） | **烘焙灌装值**——出厂镜像时真正写进板子的那份 |
| `deploy/config/10-device.json`（`mouse` 段 **2 键**） | **兜底 seed**——仅当上一份不存在时用 |

**引用配置值前必须核对绝对路径 + mtime。**（团队审查曾两轮引了不同的一个，得出相反结论。）

### 5.2 ★★ `usbproxy/usb-proxy` 是预编译 ELF 直接入 git

改了 `usbproxy/*.cpp` **却没有重建这个 ELF** ⇒ **产物不随包，板上跑的还是旧二进制**。
重建方式（就地，注意 `make clean` 会先删掉它）：

```bash
cd /mnt/c/ttbox-local/usbproxy   # WSL 内
make CXX=aarch64-linux-gnu-g++ \
  CPPFLAGS="-I/usr/include -I/usr/include/lua5.4" \
  LDFLAGS="-pthread -L/usr/lib/aarch64-linux-gnu -Wl,-rpath,'\$\$ORIGIN/lib'" \
  LDLIBS="-lusb-1.0 -llua5.4 -ljsoncpp" clean all
make SHA256SUM=sha256sum checksum     # 重算 usb-proxy.sha256
```
然后 `git add usbproxy/usb-proxy usbproxy/usb-proxy.sha256` 并提交。
出货脚本会校验：`.sha256` 一致（硬 FAIL）+ 可由 Makefile 重建（硬要求）。

### 5.3 ★★ 字段链路：同一件事四个名字，分属不同层

| 字段 | 含义 | 影响 |
|---|---|---|
| `crop_width/height` | **硬件采集裁剪**（V4L2 `VIDIOC_S_SELECTION`） | 决定采多少像素 |
| `runtime_profile.capture.width/height` | **AI 推理 ROI / 选靶半径** | 决定送模型哪块、选靶范围 |
| `runtime_profile.video.crop_*` | 面板设过的采集裁剪（优先于全局 config） | 同上第一行 |

源码自己写了「**勿混**」（`RuntimeProfiles.hpp`）。**引用任何字段做计算前，必须能答出
「从哪个文件 → 经哪几个函数 → 最终影响哪个产出」**，答不全就只能定性、不能进量化表。

### 5.4 ★ 板端时区是 UTC，比北京时间慢 8 小时

看日志先对齐时间（板子无 RTC）。

### 5.5 ★ plink 的坑

- plink 在 `C:\Users\Administrator\bin\`（**不在 PortableGit 里**）。
- Git Bash 调原生 exe **要双写斜杠**：`taskkill //PID 123 //F`（单写会被 MSYS 当路径吞掉，rc=0 但输出为空）。
- 多行走 stdin 必须**先去 CR**：`tr -d '\r' < 本地脚本.sh | plink <host> "bash -s"`。

### 5.6 ★ 其他一次性坑

- **中文路径致 core ctest 假失败** ⇒ 必须用 `C:/ttbox-local` 软链。
- **OTA 私钥是 Ed25519**（见 §0）。
- **更新器从 `current` 加载** ⇒ 从旧版本跳上来那一跳跑的是**旧 updater**。
- **回切必须「软链 + systemd unit」一起退**（只切软链会留下 unit 指向新版本 ⇒ `exec not found` 重启循环）。
- **core 跑 `User=root`、web 跑 `User=ttbox`（板端无 sudo）** ⇒ 硬件写操作（EDID/USB 模式）必须走 core IPC。

## 6. 推送 GitHub（本仓库 public，必扫凭据）

```bash
git diff <远端sha>..HEAD > /tmp/_pushdiff.txt
grep -c '<当前版本号>' /tmp/_pushdiff.txt      # 正对照：必须 > 0（证明扫描器在工作）
grep -icE "password|passwd|passphrase|secret|api[_-]?key|token|private key|AKIA|ghp_|-----BEGIN" /tmp/_pushdiff.txt   # 逐条核实
git ls-files | grep -iE "\.(pem|key|crt|p12|pfx)$|id_rsa|id_ed25519|creds"   # 必须空
```

★ **远端 `TTBOX-C.git` 是「单 commit 无父基线」风格**（干净基线，无历史）。
更新方式：把当前 tree 压成无父提交再 force-push——

```bash
TREE=$(git rev-parse HEAD^{tree})
NEW=$(git commit-tree $TREE -m "TTBOX V<版本> 基线：<概要>")
git update-ref refs/heads/baseline $NEW
git push --force ttboxc baseline:main        # ★ 需所有者授权
```

**当前基线**：`02ee35f`（V1.0.63，840 文件）｜**旧基线回滚锚点**：`547cbdc`（V1.0.51，987 文件）。

## 7. 当前状态与已知问题（2026-10-09 交接快照）

**版本水位**：源码 / 云端 latest / 包库 = **V1.0.63**；板端 current = **V1.0.63**。

**V1.0.63 含什么**：选靶器重构（三层瀑布 → 单层打分 + IoU 判定 + 锁定保持）、PID 输出限幅、
7 项 P0 修复（AI 按键分账、非阻塞 send 等）、去 Python 清理、全项目补注释。

**已知问题（未修，按影响排序）**：

1. **★★ dwc3 内核 bug 导致鼠标透传偶发失效**（最高优先）
   - 现象：`dmesg` 见 `dwc3 fc000000.usb: No resource for ep0out` + `device reset` 风暴 ⇒ 被控电脑端鼠标失灵
   - **触发条件**：gadget 重配动作（usbproxy 重启 / OTA 升级 / 鼠标重枚举），每次 1-2 秒后自愈
   - **根因**：RK3588 内核已知 bug（usbdp PHY 重初始化 → ep0out enable 时序失败），**与 TTBOX 代码无关**
     - 证据：持久化内核日志显示 9/30 起持续存在（10/4 峰值 185 次/天）
     - 修复已存在：Sebastian Reichel `phy: rockchip: usbdp: Clean up the mess` v14/v15（2026-08/09），
       内核需含此补丁；**当前内核 `5.10.0-1012-rockchip`（2024-08 构建）不含**
   - **缓解**：① 拔插被控电脑侧 USB 线（patch 明确支持 cable replug 恢复，最快）
     ② usbproxy 侧 `--set_config_ack_before_configure` 开关（未启用） ③ 换/编含修复的内核
2. **选靶器遗留次要问题**（已记录未修）：门控参考点错配（量框心、保护瞄准点）、
   开火禁切只挡 1 帧、类别优先旋钮空转、一处过期注释。
3. **`ModelRuntimeState` 假覆盖**：整组方法生产引用 = 0，只有测试在用（删不删由所有者定）。

**板端遗留状态**：排查鼠标问题时曾把板端 usbproxy 二进制临时回滚为 V1.0.62 版，
原版备份在板端 `/tmp/usb-proxy-v1063.bak`；下次 OTA 重装会自动恢复为 V1.0.63 版。
