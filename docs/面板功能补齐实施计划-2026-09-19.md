### 已确认的两条关键语义

1. **自动开火**（面板提示原文，index.html:5602）：
   "每条配置独立决定按住热键和目标类别；**准星进入匹配目标框内即可触发**。"
   ⇒ 触发条件 = `按住热键` ∧ `准星坐标落在匹配类别目标的框内`（再叠进入延迟与冷却）。
   ⇒ **准星找色是自动开火的前置**，两者不能颠倒实现。
2. **连点**（面板提示原文，:5617-5620）：
   "按住该键时循环模拟左键点击"；`press_base_ms`=170、`interval_base_ms`=13，
   "实际会加入随机浮动，偶尔会慢一拍"。

### 需要新增的底座能力

`自动开火` 与 `连点` 都要往 HID 注入**按键**，而当前 Core 做不到：

- `core/src/output/MouseControlClient.hpp:37` 只有 `send_move()`，**没有按键命令**；
- `core/src/output/OutputBackend.cpp:56` 的 `UsbProxyMouseControlBackend::mouse_button()`
  是个空壳，只 `return gate_allows()`，什么都没发；
- `core/src/output/LocalHidBackend.cpp:101` 的 `mouse_button()` 同理，注释写着"保留接口"。

usb-proxy 侧**已经支持**了：`usbproxy/mouse_control.cpp` 的 `kButtonCmd(5)`
载荷 `<BB button,action>`，button 1~8、action ∈ {down=1,up=2,click=3}。
所以底座这一层是"把已有的协议接上"，不是新造。

### T2-2 Pid1Controller 加 ki 积分项

- `MouseProfile` 加 `ki_x` / `ki_y`（默认 0）。
- `Pid1Controller` 加积分累加 + 抗积分饱和（输出 clamp 时停止累积）。
- **约定：默认 ki=0 ⇒ 输出与当前逐字节一致**，照 `ContinuousLeadConfig` 的先例
  （见 MouseTypes.hpp:242-246 的注释），保证"没开就等于没加"。

输出物：`core/src/aim/Pid1Controller.hpp`、`core/src/mouse/MouseTypes.hpp`、
web 翻译层（`CONTROLLER_NUMS` 加两个键）+ 回读。
验证方式：Core 单测（ki=0 输出不变 / ki>0 消除稳态误差 / 饱和不累积）。

### T2-3 连点 rapid_fire（依赖 T2-1）—— ⚠️ 已作废（2026-09-24）

> **作废原因**：BB_927 合并后，连点功能由 `trigger2`（连点/连发，见自动开火分区）接替，
> 面板不再单独暴露连点入口；`rapid_fire` 配置块与占位界面已删除。
> 已装机设备 JSON 里的旧 `rapid_fire` 字段保留不删（读侧忽略），不会再写回。
>
> 原设计（存档）：字段 `enabled` / `hotkey` / `press_base_ms`(170) / `interval_base_ms`(13)；
> 行为 = 按住热键时循环按下/松开左键，时长与间隔按随机区间抖动，每 ~8 次插入一次"慢一拍"。

### T2-4 自动开火 auto_trigger（依赖 T2-1 + T2-6）—— ⚠️ 已作废（2026-09-24）

> **作废原因**：同上，由 BB_927 的 `trigger`（自动开火）/`trigger2`（连点/连发）接替，
> `auto_trigger` 配置块与多 profile 占位界面已删除；旧字段保留不删、读侧忽略。
>
> 原设计（存档）：每条 profile `hotkey` / `fire_mode`（tap|spray）/ 目标类别掩码 /
> `enter_delay_min..max_ms` / `cooldown_min..max_ms` / `spray_release_delay_ms`(500) /
> `continuous_mode` / `spray_recoil_assist`；触发 = 热键按住 ∧ 准星在匹配目标框内 ∧ 过冷却。

行为：
- 触发条件 = 热键按住 ∧ 准星落在匹配类别目标框内 ∧ 距上次开火超过冷却。
- 首次进入：等待 `enter_delay` 随机值再按下。
- `tap`：按下 → 松开（短点），冷却随机后再判。
- `spray`：按下并保持，到 `spray_release_delay_ms` 松开；
  `continuous_mode` = 只要条件成立就不停循环；`spray_recoil_assist` = 扫射期间叠加压枪。

### T2-5 自动背闪 auto_back_flick

字段齐全（`turn_pixels`3000 / `wait_ms`150 / `steps`100 / `cooldown_ms`3000 /
`turn_random`50 / `return_random`20 / `random_direction` / `dodge_away_from_target` /
类别掩码）。
行为：检测到匹配类别目标 → 横向移动 `turn_pixels`（分 `steps` 步平滑，方向按
`random_direction` 或按目标位置反闪）→ 停 `wait_ms` → 分 `steps` 步回正 →
冷却 `cooldown_ms`。位移通过既有输出链发（`send_move`），**不依赖 T2-1**，
但保留依赖声明是因为要读类别过滤。

### T2-6 准星找色 crosshair

字段：`detection_enabled` / `only_when_fire_held` / `fire_hotkey` /
`roi_w`、`roi_h`（2-150，围绕画面中心）/ 多个色彩槽（每槽 `enabled` + 一种颜色
∈ {red,green,blue,cyan,white,black}）。

行为：在中心 `roi_w × roi_h` 区域按启用槽的颜色做像素匹配，得到准星坐标；
`only_when_fire_held` 开启时只在按住 `fire_hotkey` 时输出结果。
输出供 T2-4 判定"准星是否在目标框内"；未检测到则回落到画面中心。

实现位置：`core/src/pipeline/`（`AimTargetTask.hpp:19-20` 已有死声明
`crosshair_detected` / `AimPoint crosshair`，正好接上）。

### T2-7 风扇调速 fan_control

字段：`enabled` / `temperature_source`(auto) / `start_celsius`(45) / `full_celsius`(70) /
`min_pwm_percent`(100) / `max_pwm_percent`(100) / `stop_hysteresis_celsius`(3)。

行为：温度 ≤ `start` → `min_pwm`；≥ `full` → `max_pwm`；中间线性插值；
降到 `start - 滞回` 以下才回到 `min_pwm`。
改造点：`core/src/app/Application.cpp:456-465` 现在是无条件 `pwm << 255`，改成
启动时读配置、按需闭环；`enabled=false` 时保持现状（满转，防热节流）。

### T2-8 热键保护 hotkey_guard ✅ 已完成（并入 T2-0，提交 `e6b7094`）

落地方式与本节原规格的一致之处：字段 `enabled` / `toggle_hotkey`，按一下切换，
挂起状态经 `/api/state` 的 `state.aim.hotkeys_suspended` 回读。

实现上多做了一件事，记在这里以免后来者困惑：挂起**不是**只在瞄准那一处生效 ——
AimThread 是把物理按键位图清零，于是所有读这个位图的链路（瞄准 Gate、压枪，以及后续
要挂上来的连点/自动开火）一并失效。这样后面几批不用各自再写一遍挂起判断。

字段：`enabled` / `toggle_hotkey`(middle)。
行为：按一次 `toggle_hotkey` 在"热键生效 / 全部挂起"之间切换；
挂起状态经 `/api/state` 的 `state.aim.hotkeys_suspended` 如实回读。

## 三、每批的统一验证流程（RK3588 固定流程，不可裁剪）

1. Windows 本地改码 → 本地完整测试（编译 → 单测 → 功能 → 接口 → 回归）；
   本地没 PASS 不许上板。
2. 本地 PASS 后进 WSL 交叉编译 ARM64 → 检查架构/依赖/版本/打包。
3. 上板真机测试：只验真实硬件与真实运行环境（HID 注入、RTP 采集、类别过滤）。
4. 板端发现 Bug → 回 Windows 改 → 重跑 1~3，绝不在板端改正式源码。
5. 全部通过才算该批完成。
