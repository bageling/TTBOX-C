## 四、服务器发布

桥接层管理路由只监听 `127.0.0.1:3100`，外网 `/api/` 走的是 license_system，
所以发包必须在服务器本机做：

```bash
# ① Windows → 服务器（plink 灌字节流；服务器回显 sha256 与本地逐字符相同）
plink -ssh -P 10015 … "cat > /tmp/ttbox-1.4.9.ota.tgz; sha256sum /tmp/ttbox-1.4.9.ota.tgz" \
  < ttbox-1.4.9.ota.tgz
# ② 服务器本机发布
curl -sS -X POST -H "X-Admin-Token: <BRIDGE_ADMIN_TOKEN>" \
  --data-binary @/tmp/ttbox-1.4.9.ota.tgz \
  "http://127.0.0.1:3100/api/ota/publish?version=1.4.9&publish=1"
```

返回 `{"ok":true,"version":"1.4.9","bytes":3219806,"sha256":"f7adfe1c…","key_id":"ttbox-ota-2026b","published":true}`。
服务器用自己的私钥重签旁车（`key_id` 相同、`sha256` 与我们本地一致，`signature` 因 `built_at` 不同而不同属正常），
自校验 `signature_ok=true`。外网 `GET /ota/latest?current=1.4.8` 返回 1.4.9 的
`package_url` / `sign_url`（两者皆 https，且 `sign_url == package_url + ".sign.json"`）。

## 八、本轮修掉的缺陷

### S8 在线激活 1 分钟内掉授权（P0）

**根因是时区错配**，不是 403 文案问题：桥接层按 UTC 写 `online_sessions.lastHeartbeat`，
`license_system` 的 Sequelize 配 `timezone:'+08:00'` 去读，每条活跃会话凭空老 8 小时；
`license/api/src/scheduledTasks.js` 每分钟跑 `checkTimeout()`，超阈值一律置 `isValid=0`
⇒ 盒子下次心跳收 403 ⇒ core 掉回 restricted。实测会话 `id=23` 被读成
`2026-09-19T05:02:37Z`（差 8h），算出 age 29128s ≫ 180s 判超时。

修了四层：

| 层 | 改动 |
|---|---|
| 根因 | 服务端 `license/api/src/config/database.js`：`timezone:'+08:00'` → `'+00:00'` |
| 阈值 | 服务端 `license/api/.env`：`HEARTBEAT_TIMEOUT=30` → `180` |
| 契约 | 服务端 `bridge/src/license.js`：403 拆两句（强制下线 vs 登录状态已失效） |
| 盒子自愈 | `plugins/web/lib/heartbeat_worker.py`：403 先判会话丢失 → relogin 自愈（上限 3 次）；强制下线/卡密到期仍锁 core |

盒子侧改动随 1.4.9 上板，新增 5 条单测在旧逻辑上全红、恢复后全绿（反向验证）。
服务端改动即时生效，板上复测见第六节。

### S9 license 后端不是 systemd 托管（运维隐患）

原先 `node src/app.js` 是手工起的孤儿进程，`systemctl` 里查不到，崩了或关机重启不自拉起，
表现是「面板和 `/api/` 一起挂」。新增 `/etc/systemd/system/ttbox-license.service`
（`Restart=on-failure`，`.env` 由 dotenv 自动加载）并 `enable --now`。
现役 `ttbox-bridge` / `ttbox-license` / `nginx` 三个单元全 active。

## 九、遗留问题

1. **S1（唯一阻塞项，等业主）**：板上 `/root/ttbox-src/tools/license/.testkeys/` 存着与
   core 内嵌公钥**配对**的授权私钥，拿到设备即可自签任意授权卡；同目录还有已作废的 OTA 2026a 私钥。
   `/root/ttbox-src` 是 88 MB 源码副本，属主 uid 197108（Windows scp 残留）。
   需业主确认**出厂镜像是否以本板为模板**——若是，必须先清残留并按 S1-A 轮换密钥。
2. **测试卡 `B9TV-****-****-****`**（完整卡号不落库）：本轮为验证在线激活新发，绑在 `opi-9ecf266dc8154491`，
   有效期至 2026-10-19。**当前保留着**，因为删了板子就掉回未授权、没法演示；
   需要清理时在面板或 DB 删 `licenses` 对应行即可。
3. **口径观察项**：`/api/license` 里的 `app_version` 是 `2026.08.03.1`、`core.version` 是 `2026.05.16`，
   与 `/api/state.app_version`（1.4.9）不是一个东西，但同屏出现容易让人误判成 S7 复发。
   建议前端加标签区分，或在文档里写清各自含义。
4. **证书续期**：Let's Encrypt YE1，**2026-12-18 到期**，手动 DNS-01 两阶段，到期前必须人工重跑。
5. **`test_hotkey_guard` 负载下偶发红**（见第二节），建议改为轮询等待。
6. **慢链路**：服务器→外网下载实测约 13 KB/s，3 MB 包要 5 分钟。板端 OTA 会长时间显示
   `RUNNING`，验收时别当卡死；长期看值得让业主升带宽或换分发方式。
