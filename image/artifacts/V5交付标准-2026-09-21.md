## 八、本版实做修正与风险披露（2026-09-21）

### 8.1 ★ 发现并修掉一处「文件在 ≠ 生效」的隐藏缺陷

V4 及以前的做法是：SSH 由 systemd 层 mask，另写 `/etc/ssh/sshd_config.d/**99**-ttbox-service.conf`
（`PermitRootLogin yes` + `PasswordAuthentication yes`）供"日后恢复 SSH 时生效"。

**这个"恢复后就能登"是假的。** 实测（chroot 内 `sshd -T`）：

```
[A] 现状（60-cloudimg-settings.conf 在前 / 99-ttbox 在后）：
    port 22
    permitrootlogin yes
    passwordauthentication no      ← ★ 生效值仍是 no
[B] 把覆盖文件改名为 00- 之后：
    passwordauthentication yes     ← 这才真的能口令登录
```

根因：`sshd_config` 对同一参数取**首个出现的值**（first-obtained-wins），而镜像自带
`60-cloudimg-settings.conf` 写的是 `PasswordAuthentication no`；`99-` 排序在它之后，
整段被忽略。所以要覆盖，**覆盖文件的序号必须早于 60**。

处置：V5 改用 `00-ttbox-service.conf`，并删除旧的 `99-ttbox-service.conf`；
同时在 04 §7 与自检 H2（S5/S6/S7）以 `sshd -T` 的**生效值**为准收口。

### 8.2 其它实做修正

| 项 | 标准原稿 | 实做 |
|---|---|---|
| enable 范围 | `systemctl enable ssh.service ssh.socket` | **只 enable `ssh.service`**（socket 与 service 同时 enable 会争抢 :22；Ubuntu 默认亦只 enable service）。socket 保持未 mask、未 enable |
| 口令哈希 | `chpasswd`（发行版默认 yescrypt） | `chpasswd -c SHA512` —— 为了能在宿主用 `openssl passwd -6` **离线复算**（yescrypt 复算不了）。20 位随机口令下强度差异无实际影响 |
| 构建方式 | 手动逐条 `run_in_img.sh` | 一次性驱动 `image/v5_bake.sh`（一次 WSL 会话内完成，防挂载丢失） |
| 回写 | 复用 `98_writeback.sh`（要求目标文件已存在） | 驱动内内置回写（tmp + 双向 sha256 + 原子改名），目标为新建的 `-V5.img` |
