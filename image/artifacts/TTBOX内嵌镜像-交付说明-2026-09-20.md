## 二、镜像里改了什么

### 阶段一 · 拿到 root 级操作面
把镜像 loop 挂载进 WSL（`qemu-user-static` + binfmt 跑 arm64 用户态），直接对 ext4 根分区做读写。全过程在 WSL 本地 ext4 副本 `work.img` 上操作，最后原子回写。

### 阶段二 · 给 TTBOX 权限（客户无 SSH，TTBOX 拿最高权限）

**提权模型：不用 sudo、不用 polkit。** 最高权限由 systemd 单元承载（下表 `User=`/`Group=` 逐条来自 `deploy/systemd/*.service`，不是推断）：

| 单元 | 运行身份 | 说明 |
|---|---|---|
| ttbox-core.service | User=root / Group=ttbox | 主进程，持有 HDMI 采集 / NPU 推理 / 鼠标注入；组 ttbox 让它能开 group 属主的 socket 与配置 |
| ttbox-ota.service + ota.path | root / root | 更新器，落任务即触发 |
| ttbox-usbproxy.service | root / ttbox | USB gadget 注入 |
| ttbox-edid.service | 未声明 User= ⇒ root | 开机把 hdmirx 的 edid/status 节点收敛成 root:ttbox 0660（EDID 权限自愈，无需自写 udev 规则） |
| ttbox-web.service | ttbox / ttbox | Web 面板，靠组 ttbox 连 core.sock |
| ttbox-preview.service | ttbox / ttbox | 低帧预览 |
| ttbox-ensure.service/timer | 未声明 User= ⇒ root | 自愈巡检 |

**新增账号**：`ttbox`（uid/gid 999，video 组，shell = nologin，**不在 sudo 组**）。
**FHS 目录**：`/etc/ttbox`、`/var/lib/ttbox`（models/hid/activation/update/ota/jobs/motion-profiles/presets）、`/run/ttbox`、`/var/log/ttbox`，属主与权限逐条对齐 `scripts/ttbox_fhs_init.sh`。

**补的依赖（用 `ldd` 量出来的，不是照文档抄的）**：
`librga2`、`libopencv-core4.5d`、`libopencv-imgproc4.5d`、`python3-flask`、`python3-waitress`、`v4l-utils`。
`libtbb2` 随 opencv 带进来；`python3-cryptography` 基础镜像自带。**不需要 numpy**（板端本来就没有，TTBOX 跑得好好的）。

**HDMI RX 不需要改引导**：内核 `CONFIG_VIDEO_ROCKCHIP_HDMIRX=y`，厂商 DTB 已启用，`rk3588-hdmirx.dtbo` 在位，`extlinux.conf` 与原厂**逐字节相同**（sha256 `3fab0431…` 未变）。

### 阶段三 · 客户交付姿态固化

| 动作 | 目的 |
|---|---|
| mask `ssh.service` / `ssh.socket` | 客户没有任何 SSH 登录面 |
| `touch /etc/cloud/cloud-init.disabled` | 去掉首启不确定性（原版会建 `ubuntu/ubuntu` 账号并开 ssh_pwauth，与"无 SSH"冲突） |
| 固化 `/etc/netplan/01-ttbox.yaml`（0600） | cloud-init 不再生成网络配置，镜像必须自带；内容复刻板端已验证的 DHCP 配置 |
| `/var/log/journal` 持久化 | 现场排障要有日志 |
| root 控制台口令设为 `root`（同开发板） | 关掉 cloud-init 后**必须**留一个入口，否则出问题完全进不去 |
| 清 machine-id / SSH host key / 日志 / apt 缓存 / bash 历史 | 一机一密、出厂干净 |

## 三、烧录步骤

镜像没动分区表，按你平时烧 RK3588 的流程走即可。

**方式 A · SD 卡（推荐先这样验）**
1. 用 balenaEtcher 或 `dd` 写卡：
   ```bash
   # Linux / WSL（先确认卡名，写错盘会毁数据）
   lsblk
   sudo dd if=ubuntu-22.04-preinstalled-server-arm64-orangepi-5-plus.img of=/dev/sdX bs=8M conv=fsync status=progress
   sync
   ```
   Windows 下 balenaEtcher 选 img → 选卡 → Flash。
2. 卡插板子，上电。首启会比平时慢一些（systemd 要生成 machine-id 并做一次开机自检）。

**方式 B · eMMC / SPI-NOR（量产）**
用 `rkdeveloptool`（maskrom 模式）或板子现有的 `dd` 到 `/dev/mmcblk0`；与你们现有量产流程一致。

**开机前提醒**：TTBOX 要 HDMI **输入**（采集源）和一路 USB **从口**（注入端），别只插网线就以为能跑。

## 四、首次开机预期

- **没有 SSH**：`ssh root@<ip>` 会被拒（服务被 mask，不是配置错）。
- **进系统走控制台**：HDMI 显示器 + 键盘，或串口，账号 `root` / 口令 `root`。
- **网口自动 DHCP**：`ip a` 应看到 `en*` 或 `eth*` 拿到地址。
- **TTBOX 自启**：`systemctl status ttbox-core ttbox-web ttbox-preview ttbox-usbproxy ttbox-edid`
- **Web 面板**：`http://<板子IP>:8000`（端口在源码里定死 `plugins/web/lib/paths.py::WEB_PORT_DEFAULT = 8000`，不读环境变量）
- **模型是空的**（按你的要求保持干净出厂）：`/var/lib/ttbox/models` 为空，需要自行放模型再在面板里选。

## 五、上板验收清单（这些 chroot 里判不了，只能真机测）

WSL 里能静态度量的都过了（见 `image/artifacts/selfcheck-2026-09-20.txt`）；下面这些**必须上板**：

```bash
# 1) 五个服务真的活着（chroot 内 systemctl 会假成功，不可信）
systemctl is-active ttbox-core ttbox-web ttbox-preview ttbox-usbproxy ttbox-edid ttbox-ensure.timer

# 2) HDMI 采集设备在位，且确认是 hdmirx 而不是别的 node
cat /sys/class/video4linux/video*/name
v4l2-ctl --list-devices

# 3) NPU 就绪
dmesg | grep -i rknpu ; ls -l /dev/rknpu*

# 4) USB gadget 注入面（在【被控那台 PC】上看鼠标是否多了一个设备）
ls /sys/class/udc/ ; systemctl status ttbox-usbproxy

# 5) 自检器再跑一遍（板上口径）
bash /root/ttbox-src/scripts/ttbox_doctor.sh
bash /root/ttbox-src/scripts/ttbox_release_verify.sh

# 6) 面板 + 授权 + 一次完整推理（放模型 → 面板选模型 → 看预览出帧、看注入生效）

# 7) 交付姿态：确认客户真的连不进来
systemctl is-enabled ssh    # 期望 masked
```

## 六、第一版漏了什么、本版怎么补的

第一版自检 A–J 全绿，但**只查了"产品树 + 服务 + 交付姿态"，没查"客户开机后要走的第一步"**。
拿开发板实况逐个目录对照后，挖出两个交付阻断项：

**缺陷 1 · 客户根本激活不了（致命）**
镜像里没有 `/opt/ttbox/config/default.json`，也就是缺 `cloud.license_base_url` / `app_secret`。
这两个字段**没有编译期缺省**（`plugins/web/lib/cloud_client.py` 明写），缺了 `card_login` 直接
fail-closed ⇒ 客户在激活页输任何卡密都失败，还会误以为是服务器挂了。
而 `cloud_client.py:41` 白纸黑字写着「板端 default.json **出厂即含** license_base_url/app_secret」——
出厂镜像本来就该带。已补：凭据文件 0640 `root:ttbox`（世界不可读、ttbox 组可读）。

**缺陷 2 · 面板"保存预设"会报错**
`presets_dir()` = `/opt/ttbox/presets`，代码里是 `mkdir(parents=True)`。开发板能建出来，
只因它的 `/opt/ttbox` 是 777（开发检出遗留）；出厂我把 `/opt/ttbox` 收紧成 0755 root:root，
于是 `User=ttbox` 的 web 建不出来 ⇒ PermissionError。出厂预置了 presets 与 motion-profiles，
并**以 ttbox 身份真写了一次文件**当证据（不靠 stat 权限位猜）。

**顺带修的**：`10-device.json` 之前没换成你要的调参版——步骤 02 在我的 factory 覆盖文件到位之前
就跑完了，装进去的是 1065 字节的仓库种子。本版是 3428 字节的开发机版（capture 320x320）。

**自检补了 F2 段**：云端凭据存在/合法/权限/ttbox 可读 + 两个目录 ttbox 真可写，
让这类"开箱可用性"以后不可能再悄悄漏掉。

## 七、遗留事项（要不要处理你定）

1. **`ttbox_release_verify.sh` 有个假阳性，我已修 Windows 源码，但板子上那份没动。**
   现象：它拿 `ldd` 回显的 `.../bin/./../lib/librknnrt.so` 去和 `.../lib` 做**字符串前缀**比较，带 `..` 必然不匹配 ⇒ 健康的 release 也报 `FAIL 设备库解析到 release 外`。真机复现过：板子上现在跑就是 rc=1，唯一失败项就是它。
   修法：两边都先 `readlink -f` 归一化再比。改的是 `scripts/ttbox_release_verify.sh`，**不随 payload 出货**，所以要生效得重新同步一次源码快照到板子。
2. **`10-device.json` 里 `runtime_profile.model_id = "EP"`，但模型目录是空的。** 客户首启如果直接点启动，会指到一个不存在的模型。要不要把这台机器调好的模型一起打进去，或者把默认 `model_id` 改成空？
3. **`plugins/model/bin/ttbox-model.py` 第 4 行是绝对导入 `from model_service import ...`，而同名模块在上一层目录。** 现在没有任何 unit 或加载器会拉起它（产品 docstring 自己写了"占位，生产推理在 Core"），所以不影响运行；真要被当独立进程拉起来会 ImportError。改也就一行（把父目录塞进 `sys.path`），但会动到 payload 和 manifest，不建议现在动。
4. **root 口令是 `root`**，与开发板一致。要换成别的，告诉我值，我改完重新出镜像。
