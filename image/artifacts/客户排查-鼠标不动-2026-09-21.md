# 「鼠标不能动」排查口径（可直接发客户）

> 现场反馈："鼠标透传用不了，鼠标不能动"。
> 下面按顺序走，**每一步都能独立排除一类原因**，走完基本能定位。

---

## 第 0 步：先确认是哪一种"不动"

- **A 类**：盒子上插着鼠标，在电脑上动它，电脑光标**完全不动** → 链路问题，走第 1～3 步。
- **B 类**：物理鼠标能正常带动电脑光标，只是**AI 不帮忙修正** → 开关/热键问题，走第 4 步。

两类原因完全不同，先问清这一句，能省一大半时间。

---

## 第 1 步：盒子上到底插没插 USB 鼠标（A 类最常见原因）

「完整透传」模式下，**盒子上必须插着一个 USB 鼠标**，盒子才会向电脑"变成"一个鼠标。
盒子上没插鼠标，盒子那边就卡在等鼠标，电脑上什么都看不到。

- 盒子上有鼠标 → 进第 2 步
- 盒子上没有多的鼠标 → 二选一：
  1. **找一个 USB 鼠标插到盒子的 USB-A 口**（推荐，改动最小、当场生效）；
  2. 切**「合成模式」**（不需要外接鼠标）：用控制台执行
     `sudo scripts/ttbox_usb_mode.sh set synthetic`，然后 `sudo systemctl restart ttbox-usbproxy`；
     切回完整透传用 `sudo scripts/ttbox_usb_mode.sh set full`。

> 面板上不再提供模式切换（浏览器里那个开关改不了 systemd 里的真实模式，已下线）。面板鼠标页只**显示当前生效模式**；要切换走上面的命令。

> 注意：无线鼠标的接收器、以及"键盘+鼠标"一体的接收器，有可能不被识别，优先用**有线鼠标**试。

---

## 第 2 步：USB 线插对没有

- 线必须是**盒子 → 电脑**，不是电脑 → 盒子。
- 盒子这一头要插在**设备口（OTG 口）**，不是只做主机（host）的口。插错口，盒子不会被电脑识别。
- 插好后看电脑：设备管理器 / 系统信息里**有没有多出一个鼠标设备**。
  - 有 → 进第 3 步
  - 没有 → 换线（有些线只能充电、不能传数据）、换口、换电脑 USB 口再试。

---

## 第 3 步：盒子上的服务还活着吗

在盒子的控制台（显示器或串口，用随附口令登录）执行：

```bash
systemctl is-active ttbox-usbproxy        # 期望：active
systemctl status ttbox-usbproxy --no-pager | tail -20
```

- 看到反复出现 `Waiting for a USB HID mouse on the Orange Pi side...`
  → 还是第 1 步的问题：盒子上没有可识别的鼠标。
- 看到 `layout_mismatch`（鼠标报告布局不被支持，1.5.29 起会打印诊断）
  → 把整段诊断连同鼠标型号发回来，这是要改代码才能适配的情况。
- 看到别的报错，把 `journalctl -u ttbox-usbproxy -n 100` 的输出发回来。

---

## 第 4 步：AI 不修正（B 类）

三个条件**同时**满足才会动，缺一个都不动：

| # | 条件 | 在哪看 |
|---|---|---|
| 1 | 总输出已开（"启用鼠标输出"） | 面板鼠标相关页 |
| 2 | 鼠标注入已开 | 面板鼠标相关页 |
| 3 | **瞄准热键正被按住，且热键是鼠标按键** | 面板"热键"下拉 |

⚠️ 热键说明（这条最容易错）：

- 热键是**鼠标按键**（下拉可选项：左键 / 右键 / 中键 / 两个侧键），**不是键盘按键**。
- **按住键盘 Shift 没有任何作用。** 配置文件里那个 `KEY_LEFTSHIFT,KEY_RIGHTSHIFT` 是历史遗留字段，运行时不读。
- 请到面板把"热键"下拉明确选成一个键（例如右键），然后**按住鼠标上那个键**再试。

---

## 需要回传的信息（便于进一步定位）

1. A 类还是 B 类？
2. 盒子上插的是什么鼠标（型号/有线无线）？
3. 线插在盒子的哪个口？电脑上能看到鼠标设备吗？
4. `systemctl status ttbox-usbproxy --no-pager | tail -20` 的输出
5. 面板上：总输出 / 鼠标注入 / 热键下拉 分别是什么
